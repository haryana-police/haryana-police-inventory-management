How the App Works (After Login)

Haryana Police Inventory Management System
Runs on your own computer — usually http://localhost:3210

Before You Start — Opening the App

This app runs on the computer it is installed on. There is no online website and no internet connection is needed after the first start.

  1. Open the project folder and double-click run-local.bat (on other systems, run npm start).
  2. A black console window opens and must stay open. That window is the app server — closing it stops the app.
  3. Your browser opens automatically. If it does not, look at the App: line in the console and open that address — it is usually http://localhost:3210. If that port is already in use the server picks the next free one, so always open the exact address it prints.
  4. When you finish, click the console window and press Ctrl+C to stop the server.
Where your data lives: everything is stored in one file — local-data\db.json in the project folder. To back up, copy that file somewhere safe. To start fresh, delete it and restart the server; the app then re-seeds its default data.
Using it from a phone or another computer: start the server on the main computer, then on the other device open http://<main computer's IP>:3210. To find that IP, run ipconfig on the main computer and read IPv4 Address (for example 192.168.1.5). Both devices must be on the same office network, and the main computer must stay switched on.

1. The Main Screen

After logging in, you see the app window with three main parts:

  • Left sidebar — menu with Dashboard, Inventory, Transactions, Demands, Inspections, Item Issued, Reports. Click any item to switch screens.
  • Top bar — District selector, notification bell 🔔, your name and role badge, and (for admins) the Districts and Users buttons, plus Logout.
  • Main area — the content of the selected screen (cards, tables, filters).
  • Long lists — every record list (Inventory, Transactions, Demands, Inspections, Item Issued, Report details) shows up to 30 rows per page. Under the table you see “Showing X–Y of Z rows” with ◀ Prev and Next ▶ buttons and page numbers; click a number to jump straight to that page. Filtering or searching starts again from page 1.
Sidebar collapse: click the ☰ icon in the top bar to shrink / expand the sidebar — handy on small screens.

2. Dashboard

An overview screen with clickable summary cards and two quick tables. Clicking a summary card opens a detail table showing exactly what that card counted, with a search box and PDF / Excel / Word / Print export options.

  • Summary cards — Total Items, Total Quantity, Low Stock Alerts, Categories, plus one card for each condition state: Good, Poor, Damaged. Click any card to open its detail view.
  • Low Stock table — items that are at or below the minimum stock level, so you know what to re-order.
  • Recent Transactions — latest additions/removals/transfers; click View All to open the full Transactions screen.
  • Both tables show a Total row at the bottom summing the quantity column.

3. Inventory

Master list of all items and their quantities, locations, and condition.

  • + Add Item — add a new item (name, category, unit, min stock, location, condition). Enter the quantity for each condition state in the Good / Poor / Damaged boxes — the Total Quantity is calculated automatically, and the date added is recorded automatically (there is no manual quantity or date field).
  • Manage Categories — all roles can view categories; showing the button is allowed for everyone.
  • Filters toolbar — search by item name; filter by category, location, condition, and date-added range. Use Clear to reset.
  • Condition & status — every item row shows its condition breakdown with a colour bar (Good / Poor / Damaged) and a stock status badge (OK, Low, or Out).
  • Export / Print — click Download / Print ▾ to save as PDF, Excel, or Word, or print the current list.
  • Each row has an Actions button to edit or delete the item.
  • The table shows a bold Total row at the bottom that sums the quantity column for the currently filtered list.

4. Transactions

Records every change of stock to keep a full audit trail with dates, locations, and the person responsible.

  • + New Transaction and choose a type:
    • Addition (+) — new stock received (external or from a location).
    • Removal (−) — stock issued / consumed / written off.
    • Transfer — moved between two locations.
  • Search & filter — search box, date From/To, and Type filter; Clear resets.
  • Export / Print — download the filtered list as PDF / Excel / Word, or print.
  • Correction workflow: to fix a transaction, click Action → propose new quantity/notes. The request goes to the other side (e.g. the receiving district) for approval. Once approved, the transaction shows an Edited badge. A transaction can be edited this way only once — further changes need a new transaction.
Transfer transactions are approved by the receiving party; this keeps both districts in agreement about what moved.

5. Demands

Formal requests for material from another district / post.

  • + Raise Demand — select item, quantity, category, condition, urgency (normal/urgent/critical), reason, and the destination district + location.
  • Summary cards — click Total / Pending / Approved / Rejected to jump to that filtered list.
  • Search & filter — by text, status, and date range.
  • Review demand (on the receiving side): open a pending demand, see full details, then Approve & Submit or Reject (a rejection reason is required).
  • Export / Print — download as PDF / Excel / Word or print.
When you raise a demand, the target district's admin receives a notification under the 🔔 bell, so they know to review it.

6. Inspections

Records of asset inspections (Routine / Special / Annual).

  • + Add Inspection — item/asset, inspected by, type, date, location, findings, recommendations, status.
  • Summary cards — Completed / Pending / Overdue counts; click to filter.
  • Search & filter — by text, type, and status.
  • Export / Print — PDF / Excel / Word / Print.

7. Item Issued

Issue items to personnel and track returns. It works on one simple rule: Total Qty = Available + Issued + Damaged/Lost. You can never issue more than what is currently available, and quantities can never go negative.

The screen has three tabs at the top:

  • Item Stock — every item with Total Qty, Available, and Issued figures. Use the search box, category filter, or the All / Issued / Available dropdown (see below). Click any column heading to sort. The Adjust Stock button records adjustments. Each row shows View, and (if you may edit) Edit and Adjust. A bold Total row sums the quantity columns.
  • Issued Items — the full issued-items register with the person's Name, Post/Rank, BELT No., Posting, the Item, Qty still with the person, and Date / Time / Status.
  • Return History — every recorded return with quantity, condition, who received it, and remarks.

Finding items in Item Stock

  • Search — type into the search box; it looks across item name, category, unit and location. You can type several words, e.g. wireless pcs, and only rows matching all of them are shown.
  • Sort — click Item Name, Category, Total Qty, Available, Issued or Status to sort the table; click the same column again to reverse (▲/▼ shows the direction).
  • All / Issued / Available dropdown — All Stock shows everything, Only Issued shows just items that are currently issued out (issued > 0), and Only Available shows just items with stock still on hand (available > 0).

Issuing items

  1. Click + Issue Items at the top of the Item Issued screen (or the Inventory screen).
  2. In Person details, start typing a name or BELT number — matching personnel appear for instant fill. Otherwise enter name, post/rank, BELT number, and posting.
  3. Under Item details, pick a Category first — only then does the Item drop-down unlock, showing just the items in that category. Choose the item; balance chips show its Total / Available / Issued.
  4. Enter the item Quantity. You can issue items from different categories and quantities in one go: press + Add Item to add more rows (Category → Item → Qty each). You can also remove a row with the × in its corner.
  5. If any quantity exceeds the available stock, you get the message “Insufficient stock for … Only X units available.”
  6. Set date/time (usually today) and optional remarks, then press Issue Items — every row is issued together under one issue record.
After an issue is saved it is locked: you can only change the quantity. Person details, item, category, date, time, and remarks cannot be edited anymore.

Editing and cancelling an issue

  • Edit on an active issue record — only the quantity can be changed (never below what has already been returned). All other fields appear greyed-out/locked. Increasing the quantity re-checks available stock.
  • Cancel — closes the issue record and returns the remaining units to stock.

Processing a return

  1. On an active issue record, click Return.
  2. Enter the Return Quantity (partial returns are allowed — it shows how many units are still to be returned).
  3. Choose the Condition on return: Good (adds the units back to available), Damaged, Lost, or Other.
  4. Save — the stock figures update immediately and the return appears in Return History. Returns that are damaged or lost are tracked separately in the Damaged / Lost columns.

Adjusting stock

Adjust (on the Item Stock tab) lets you record Stock Added, Stock Correction (set total), Written Off, Mark Damaged, or Mark Lost. The corrected total can never be set below the units currently held (issued + damaged + lost). Every adjustment is written to the item's transaction history.

Viewing details and history

  • View on an item — Currently Issued To (who holds it now) and its Transaction History (issues, returns, adjustments).
  • Click a person's Name in the Issued Items list to see that person's Currently Issued Items and Returned / Settled Items.

Search, filter, and export

  • Issued Items — search by name / belt / item / posting / rank, plus filters for Category, Item, Posting, Rank, Status, and date range; Clear resets everything.
  • Each tab has Download / Print ▾ — export the current list as PDF, Excel, or Word, or print it. Exports include the Total row.
Issued items respect the same role limits as the rest of the app: who can issue, edit, return, and cancel is controlled by the user's role, and station/post users only ever see their own location's data.

8. Scan & Import (OCR)

Automatically read a filled application / receipt document and let the app fill in an issue record for you — always with a human verification step before anything is saved. The button Scan & Import is available on both the Item Issued and the Inventory screen; the Scans button shows every document you have imported.

Supported formats

Images (JPG / PNG / WebP / BMP), PDF (text or scanned), Word (DOCX), Excel (XLSX), and TXT / CSV. The reading is done in your browser — the file is not uploaded before you confirm it.

How it works

  1. Click Scan & Import, then click or drag a file onto the upload box.
  2. Press Scan Document. The app reads the document (progress is shown; the OCR model downloads once on first use) and automatically extracts person details — Name, Post / Rank, BELT No., Posting — and the Items + Quantities by matching against your item list.
  3. The Review & Verify screen opens with every field pre-filled and editable. Correct anything the computer misread, add or remove item rows, and check the Raw extracted text panel if you want to compare with the original.
  4. Only when you press Verify & Insert Data is anything saved: the person is created (if new), the issue appears in Issued Items, and item stock is reduced — exactly as if you issued it manually.
  5. The original document is stored with the record. Open Scans → View to see or download the original file, the person it was issued to, the items, date, and who verified it.
Items are matched by name, so scanned items must already exist in your inventory to be recognised. A quantity that exceeds available stock is blocked at verification, just like a manual issue. The scan is only saved after human verification — nothing is ever inserted automatically without your confirmation.

9. Reports

Three ready-made reports. Switch with the tabs at the top of the screen. Reports respect your role — for example, a post or station user only ever sees their own location's data in every report and export.

  • Stock Report — current stock position by item, with clickable summary cards: Total Items, In Stock, Low Stock, Out of Stock, Good Units, Poor Units, and Damaged Units. Click any card to open a detail table of exactly those items, with a search box and PDF / Excel / Word / Print export.
  • Category Breakdown — items grouped by category with quantities.
  • Location Report — stock grouped by location / station.
  • Search — type in the search box to filter the current report instantly.
  • Sort — click any column heading to sort; click again to reverse the order.
  • Download / Print ▾ — export the report as PDF, Excel, or Word, or print it.
  • Every report table has a bold Total row at the bottom summing its quantity columns; when you export a report or a card's detail view, the total row is included in the PDF / Excel / Word file and in Print.

10. Notifications (🔔 Bell)

Click the bell in the top-right corner to open the notifications panel. The red number shows unread items.

  • See new demands, access requests, approvals/rejections, and password-reset requests.
  • Use Mark all read to clear the counter.
  • Admins can act directly on some notifications (e.g. approve an access request right from the panel).
Notification scope: the Developer Admin sees notifications across all districts (up to 30), while other users see only their own district (up to 20).

11. Users & Districts (Admin Options)

  • Users — create, edit, or remove user accounts and their roles. When you edit a user you may set a new password (leave blank to keep the current one).
  • Districts — manage districts and their locations/stations (devadmin).
  • District selector — devadmin can switch the district being viewed; other users are locked to their own district.
Only create accounts for people who genuinely need access. Admin accounts are powerful — never create admin accounts for general staff.

12. Roles at a Glance

13. Good Practices

  • Always press Logout on shared devices.
  • Keep your password private — it is stored hashed and cannot be read by anyone.
  • Use Forgot Password? on the login screen if you need a reset; the admin is notified automatically.
  • Wrong login? Passwords are checked server-side; repeated failures are rate-limited for your protection.
